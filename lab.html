1.2 Files & Permissions

Everything in Linux is a file. Understanding file permissions is critical for system security.

File Operations

Shell

touch newfile.txt

# View file contents
cat file.txt              # Print entire file

# Copy, move, delete
cp file.txt backup.txt
mv file.txt renamed.txt
rm file.txt

# Search inside files

Understanding Permissions

Run ls -l and you will see lines like:

Output
-rw-r--r-- 1 root root 1234 Jan 15 10:00 file.txt
drwxr-xr-x 2 root root 4096 Jan 15 09:30 mydir
lrwxrwxrwx 1 root root    4 Jan 15 08:00 link -> file
PositionMeaning
1st char- file, d directory, l symlink
2-4Owner permissions: read (r), write (w), execute (x)
5-7Group permissions
8-10Others (world) permissions
Shell
# Change permissions
chmod 755 script.sh         # rwxr-xr-x
chmod u+x script.sh         # Add execute for owner
chmod go-w file.txt         # Remove write for group and others

# Change owner
chown user:group file.txt
chown -R user:group /mydir  # Recursive

# Symbolic notation reference
# u = user (owner), g = group, o = others, a = all
# + = add, - = remove, = = set exactly
chmod u=rwx,go=rx file
🎯 Exercise 1.2: Permission Practice

  2. Create a script: echo '#!/bin/sh' > /tmp/hello.sh && echo 'echo Hello' >> /tmp/hello.sh
  3. Try to run it: /tmp/hello.sh — it should fail with "Permission denied"
  4. Make it executable: chmod +x /tmp/hello.sh and run again
  5. Remove execute permission from others: chmod o-x /tmp/hello.sh

1.3 Pipes & Redirection

Linux has three standard I/O streams: stdin (0), stdout (1), and stderr (2). Redirection and piping let you combine commands in powerful ways.

Shell
# Redirect stdout to file
ls /etc > files.txt

# Redirect and append
echo "new line" >> files.txt

# Redirect stderr
ls /nonexistent 2> errors.log

# Redirect both stdout and stderr
command > output.log 2>&1
command &> output.log        # Bash shorthand

# Discard output
command > /dev/null 2>&1

# Pipe: send stdout of one command to stdin of another
ls /etc | wc -l              # Count files in /etc
cat /etc/passwd | grep root  # Find root entries
ps aux | grep docker         # Find docker processes

# Pipe with stderr through pipe
cat /etc/passwd /nonexistent 2>&1 | grep -i error

# Here document
cat << EOF > /tmp/config.txt
name=lab
version=1.0
EOF

# xargs: build commands from stdin
find /etc -name "*.conf" | xargs ls -la
💡 Pipe Chain Examples

cat /var/log/messages | grep "error" | sort | uniq -c | sort -nr — finds all error lines, counts unique occurrences, and sorts by frequency (most common first).

Module 2: System Administration

This module covers user management, process control, disk configuration, networking, and firewall rules — the daily work of a Linux system administrator.

2.1 Users & Groups

Linux is a multi-user system. Every file and process is owned by a user and a group. The root user has unlimited privileges.

Shell
# Show current user
whoami
id

# Show user info
id root
id $(whoami)

# User database files
cat /etc/passwd      # User accounts
cat /etc/shadow      # Password hashes (root only)
cat /etc/group       # Group definitions

# Add a user (Alpine uses adduser script)
adduser -D -s /bin/sh student

# Set password
passwd student

# Add user to a group
addgroup student docker

# Modify user
usermod -s /bin/bash student

# Delete user
deluser student

# Switch user
su - student

# Run command as root (you are already root in this lab)
sudo whoami

The /etc/passwd file format:

Output
root:x:0:0:root:/root:/bin/sh
# format: username:password:UID:GID:comment:home:shell

2.2 Process Management

Every running program is a process. Linux provides powerful tools to view, control, and manage processes.

Shell
# List processes
ps aux              # All processes, detailed
ps -ef              # Full format
ps aux | grep docker

# Real-time process viewer
top                 # Basic
top -b -n 1         # Batch mode, single snapshot

# Better process viewer (install if needed)
# apk add htop      # Not available on i386; use top instead

# Process tree
pstree

# Find process by name
pgrep docker
pidof dockerd

# Send signals to processes
kill PID            # Graceful termination (SIGTERM)
kill -9 PID         # Force kill (SIGKILL)
killall dockerd     # Kill by name

# Background and foreground
sleep 60 &          # Run in background
jobs                # List background jobs
fg %1               # Bring job 1 to foreground
bg %1               # Resume job 1 in background

# Process priority (nice values)
nice -n 10 command  # Run with lower priority
renice -n 5 -p PID  # Change priority of running process

# Show open files by process
lsof -p PID
lsof -i :80         # What is using port 80?
💡 Common Process States

R = Running, S = Sleeping (interruptible), D = Uninterruptible sleep, T = Stopped, Z = Zombie (defunct). See full list with man ps.

2.5 Firewall (iptables)

iptables is the Linux firewall framework. Alpine includes iptables and ip6tables. Docker manipulates iptables rules automatically for container networking.

Shell
# List all rules
iptables -L -v -n

# List rules with line numbers
iptables -L INPUT -n --line-numbers

# Show NAT rules (Docker uses these extensively)
iptables -t nat -L -n -v

# Default chains: INPUT, FORWARD, OUTPUT
# Default tables: filter, nat, mangle, raw

# Allow incoming SSH (example)
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Block an IP
iptables -A INPUT -s 192.168.1.100 -j DROP

# Save rules (Alpine)
iptables-save > /etc/iptables/rules.v4

# Docker's iptables impact
iptables -L FORWARD -n -v   # Docker creates forwarding rules
iptables -t nat -L DOCKER   # Docker NAT rules for port mapping
⚠️ iptables + Docker

Docker modifies iptables rules automatically to enable container networking. Be careful when manually editing iptables rules — you might break Docker's networking. Always check iptables -L -n -v before and after changes.

3.3 Conditionals

Use if, elif, else to make decisions. Test conditions with [ ] or [[ ]] (bash only).

Shell
#!/bin/sh

# File tests
if [ -e /etc/passwd ]; then
    echo "/etc/passwd exists"
fi

# Common test operators:
# -e file  : exists
# -f file  : exists and is regular file
# -d file  : exists and is directory
# -r file  : readable
# -w file  : writable
# -x file  : executable
# -s file  : non-empty
# -z str   : string is empty
# -n str   : string is non-empty
# str1 = str2  : strings equal
# str1 != str2 : strings not equal
# num1 -eq num2 : numbers equal
# num1 -ne num2 : numbers not equal
# num1 -lt num2 : less than
# num1 -gt num2 : greater than
# num1 -le num2 : less or equal
# num1 -ge num2 : greater or equal

# Numeric comparison
AGE=25
if [ "$AGE" -ge 18 ]; then
    echo "Adult"
else
    echo "Minor"
fi

# String comparison
NAME="admin"
if [ "$NAME" = "admin" ]; then
    echo "Welcome, administrator"
elif [ "$NAME" = "guest" ]; then
    echo "Welcome, guest"
else
    echo "Unknown user"
fi

# Combined conditions with AND / OR
if [ -f /etc/passwd ] && [ -r /etc/passwd ]; then
    echo "Can read /etc/passwd"
fi

if [ "$1" = "start" ] || [ "$1" = "begin" ]; then
    echo "Starting..."
fi

# Case statement
case "$1" in
    start)
        echo "Starting service..."
        ;;
    stop)
        echo "Stopping service..."
        ;;
    restart)
        echo "Restarting service..."
        ;;
    *)
        echo "Usage: $0 {start|stop|restart}"
        exit 1
        ;;
esac

3.4 Loops

Shell
#!/bin/sh

# For loop with list
for NAME in Alice Bob Charlie; do
    echo "Hello, $NAME!"
done

# For loop with command output
for FILE in /etc/*.conf; do
    echo "Config file: $FILE"
done

# C-style for loop (bash)
for ((i=1; i<=5; i++)); do
    echo "Iteration $i"
done
# In sh, use: for i in $(seq 1 5); do ... done

# While loop
COUNT=1
while [ $COUNT -le 5 ]; do
    echo "Count: $COUNT"
    COUNT=$((COUNT + 1))
done

# Until loop
NUM=1
until [ $NUM -gt 5 ]; do
    echo "Until: $NUM"
    NUM=$((NUM + 1))
done

# Infinite loop with break
while true; do
    echo "Running... (Ctrl+C to stop)"
    sleep 1
done

# Continue (skip to next iteration)
for i in 1 2 3 4 5; do
    if [ $i -eq 3 ]; then
        continue
    fi
    echo "Number: $i"
done

3.6 Text Processing

Text processing is one of the shell's greatest strengths. These tools form a powerful pipeline for data manipulation.

Shell
# grep — pattern search
grep "root" /etc/passwd
grep -i "admin" /etc/passwd        # Case-insensitive
grep -v "nologin" /etc/passwd      # Invert match
grep -c "bin" /etc/passwd          # Count matches
grep -E "^root|^admin" /etc/passwd # Extended regex

# sed — stream editor
sed 's/old/new/' file.txt          # Replace first occurrence per line
sed 's/old/new/g' file.txt         # Replace all occurrences
sed 's|/usr/local|/opt|g' file.txt # Different delimiter
sed -i 's/old/new/g' file.txt      # Edit in place
sed -n '5,10p' file.txt            # Print lines 5-10
sed '/pattern/d' file.txt          # Delete matching lines

# awk — pattern scanning and processing
awk '{print $1}' file.txt          # Print first field
awk -F: '{print $1}' /etc/passwd   # Use : as delimiter
awk '{print NR, $0}' file.txt      # Print with line numbers
awk '/pattern/ {print $2}' file    # Print $2 where pattern matches
awk '{sum+=$1} END {print sum}' nums.txt  # Sum first column

# cut — extract columns
cut -d: -f1 /etc/passwd            # First field, : delimiter
cut -c1-10 file.txt                # First 10 characters

# sort and uniq
sort file.txt                      # Alphanumeric sort
sort -n file.txt                   # Numeric sort
sort -r file.txt                   # Reverse sort
sort | uniq                        # Unique lines only
sort | uniq -c                     # Count occurrences
sort | uniq -c | sort -nr          # Most common first

# tr — translate characters
echo "hello" | tr 'a-z' 'A-Z'      # To uppercase
echo "hello world" | tr ' ' '_'    # Replace spaces
cat file.txt | tr -d '\r'          # Delete carriage returns

# wc — word count
wc -l file.txt                     # Line count
wc -w file.txt                     # Word count
wc -c file.txt                     # Byte count
ls /etc | wc -l                    # Count files

# xargs — build commands from stdin
find /etc -name "*.conf" | xargs grep -l "setting"
echo "file1 file2" | xargs rm

Containers are lightweight, isolated environments that package an application with all its dependencies.

Docker

# Remove a container

docker logs mynginx

4.5 Microservices Lab: Link Extractor

Let's build a simple multi-service application inspired by the original Docker 101 course — adapted for our Alpine i386 environment.

API Service (Python Flask)

Python
# api/linkextractor.py
cat > api/linkextractor.py << 'EOF'
#!/usr/bin/env python3
import sys
import urllib.request
from html.parser import HTMLParser

class LinkExtractor(HTMLParser):
    def __init__(self):
        super().__init__()
        self.links = []
    def handle_starttag(self, tag, attrs):
        if tag == 'a':
            for name, value in attrs:
                if name == 'href':
                    self.links.append(value)

def extract_links(url):
    try:
        with urllib.request.urlopen(url, timeout=10) as response:
            html = response.read().decode('utf-8')
        parser = LinkExtractor()
        parser.feed(html)
        return parser.links
    except Exception as e:
        return [f"Error: {e}"]

if __name__ == "__main__":
    if len(sys.argv) != 2:
        print("Usage: linkextractor.py ")
        sys.exit(1)
    for link in extract_links(sys.argv[1]):
        print(link)
EOF
Python
# api/main.py
cat > api/main.py << 'EOF'
#!/usr/bin/env python3
from flask import Flask, jsonify
import sys
sys.path.insert(0, '/app')
from linkextractor import extract_links

app = Flask(__name__)

@app.route('/')
def index():
    return "Usage: /api/<url>"

@app.route('/api/<path:url>')
def api(url):
    links = extract_links("http://" + url)
    return jsonify({"url": url, "links": links})

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
EOF

5.3 JOINs & Advanced Queries

SQL
-- Create departments table
CREATE TABLE departments (
    dept_id INT AUTO_INCREMENT PRIMARY KEY,
    dept_name VARCHAR(50),
    location VARCHAR(50)
);

INSERT INTO departments (dept_name, location) VALUES
('Engineering', 'Building A'),
('Sales', 'Building B'),
('Marketing', 'Building C');

-- INNER JOIN: only matching rows
SELECT e.first_name, e.last_name, d.dept_name, d.location
FROM employees e
INNER JOIN departments d ON e.department = d.dept_name;

-- LEFT JOIN: all employees, even without matching department
SELECT e.first_name, e.last_name, d.dept_name
FROM employees e
LEFT JOIN departments d ON e.department = d.dept_name;

-- Subquery
SELECT first_name, last_name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);

-- IN operator with subquery
SELECT * FROM employees
WHERE department IN (SELECT dept_name FROM departments WHERE location = 'Building A');

-- Create index for faster queries
CREATE INDEX idx_department ON employees(department);
CREATE INDEX idx_salary ON employees(salary);

-- Check query execution plan
EXPLAIN SELECT * FROM employees WHERE department = 'Engineering';

MySQL Replication Concepts (Theory)

MySQL replication enables data from one MySQL host (Primary) to be copied to another (Replica). Common uses:

  • Read scaling: Distribute read queries across replicas
  • Backups: Take backups from a replica without affecting the primary
  • Disaster recovery: Geographic distribution of data

Replication types:

  • Asynchronous (default): Primary does not wait for replica acknowledgment
  • Semi-synchronous: Primary waits for at least one replica to acknowledge
  • GTID-based: Uses Global Transaction IDs instead of binlog coordinates

Module 6: Kubernetes Concepts

Kubernetes (K8s) is a container orchestration platform. While this VM does not have enough resources to run a full K8s cluster, understanding its concepts is essential for modern DevOps.

⚠️ Note on Practical Kubernetes

Running Kubernetes requires significant resources (typically 2+ GB RAM, 64-bit architecture). This 512MB 32-bit VM cannot run a real K8s cluster. The content below is conceptual/theoretical. For hands-on practice, use cloud-based labs like Killercoda, Katacoda, or cloud provider playgrounds.

6.1 Core Concepts

Kubernetes is a declarative system: you describe the desired state, and K8s works to maintain it.

Key Principles

ConceptDescription
DeclarativeYou say "I want 3 replicas of this app"; K8s makes it happen
Self-healingIf a pod crashes, K8s automatically creates a new one
ScalingScale applications horizontally by adding/removing pods
Rolling updatesUpdate applications without downtime, one pod at a time
Service discoveryPods find each other via DNS names, not IP addresses

Architecture

Kubernetes has a control plane (master) and worker nodes:

  • API Server: Entry point for all K8s operations
  • etcd: Distributed key-value store for all cluster data
  • Scheduler: Assigns pods to nodes
  • Controller Manager: Maintains desired state
  • Kubelet: Agent running on each node
  • Kube-proxy: Network proxy on each node
