## Shell Characters  ( ? * [ ] ; ^ ~ )
These characters are helping us by creating functions when we interact with the shell. <br/>
<br/>`Character ? : ` It provides us letter limitation when we command a query. For example, when we run `ls /bin/a??` command, we will only see three letter files, just as /bin/apt & /bin/awk.. <br/>
<br/>`Character * : ` This character is used instead of “All”. If we use `ls /bin/a*` command we will see every file which starts with “a” and located under bin file. If we switch the position like this; “ls /bin/*a” we will see the files which ends with a and located under bin file. <br/>
<br/>` Character [ ] : ` This character helps us by giving options. If we use the command like this; `ls /bin/[a-c]*`, we will see every file which starts with a,b,c. <br/>
<br/>`Character ; : ` This character is letting us do more than one query. You should not  confuse “;” with pipe “ | “. Pipe is letting us to get interacted with commands.  When we use `uname;date;whoami` commands like this, system will reply us with OS, date and user information. If we use pipe like this; `uname|date|whoami` we will only reach to the OS information, because the commands will not interact with each other.  <br/>
<br/>`Character ^ : ` This character is used with transactions which includes negative queries.
<br/>`ls -a[^a]*` command will provide us every file that does not starts with a letter. <br/>
<br/>`Character ~ : ` This character’s name is tilde. It is equal to the home directory of Linux user.
 <br/>`cd ~` query will take us to /home/user_name directly. You can reach to other characters from [here](/https://www.cs.ait.ac.th/~on/O/oreilly/unix/upt/ch08_19.htm). <br/>

## Condition Expressions

Condition statements are expressions that control the variables used and will be used by the script. It also can control system variables, the states and values of the units such as directory & file & folder, and it can indicate how the algorithm in the script will progress. Condition expressions that satisfy queries are `if, elif, else`. <br/>
`if`= It is the first step of the condition situations, takes place at the very beginning and is used once. We need to end it with `fi`.<br/>
`elif`= Compares the 2. 3. 4.… states of the condition.<br/>
`else`= It is used in situations that do not meet any conditions.
<br/>The working principles of if expression is taking place in the script named `if.sh`. We will write a command into the script example and if there is already such a command, the echo command will tell us "There is such a command already!” If the command does not exist, the output will be; "There is no such command!" <br/>

## Comparison Operators

Comparison operators are used to compare variables with each other. We can provide the flow of the written algorithms and commands through these operators. The comparison operators are as follows:<br/>
-eq (equal) ; == ; It checks for the condition that the variables are equal to each other.<br/>
-ne (not equeal) ; != ; It checks for the condition that the variables are not equal to each other.<br/>
-lt (less than) ; < ; It checks whether one variable is less than another variable.<br/>
-gt (greater than) ; > ; It checks whether one variable is greater than another variable. <br/>
-le (less or eqaul) ; <= ; Checks whether one variable is less than or equal to another variable.<br/>
-ge (greater or eqaul) ; >= ; Checks whether one variable is greater than or equal to another variable.<br/>
Let's take a look at the comparison_opt.sh script as an example.<br/>
  
In this script, 2 numbers are given as variables and the script will check the variables with 3 different ifs.<br/>
There will be 2 queries in the first if header, "Are the values equal or not?"<br/>
There will be 3 queries in the second if header “Is the first value large? is it small? equal? "<br/>
There will be 3 queries in the third if header “is it greater than or equal? is it less or equal? are the values valid? "<br/>
  
When repeating the examples, do not forget how then and fi commands are used. <br/>

cat comparison_opt.sh

## And & Or Operators

In True / False operations, 1 means true and 0 means false. If a condition parameter is true, it returns 1 to the system, and it returns 0 if it is false. So how do we ensure that there are more than 1 condition parameter in the condition situation we have prepared? We provide this with the and & or operators.<br/>
Let's consider the and operator with an age query model with `and.sh` as an example. And operator is used by typing “&&” or -a. Both of the queries which are given for the and operator, needs to get true(1) output.<br/>


```.term1
cat and.sh
```

```
#! /bin/bash
if [[  $1 -gt 0 && $1 -lt 18  ]]
then
echo "Age is not higher than 18!"
else
echo "Age is higher than 18 or equls to 18"
fi

```

Our script here asks whether the value of $1 is greater than 0, and in the second part it asks whether it is less than 18. Both inquiries are answered with "Age is not higher than 18!". <br/>
For example, let's consider the or operator with a simple game model with or.sh. The or operator is used by typing two pipes “||” or -o. For the Or operator, it is sufficient if 1 of the queries entered gets the true(1) value. In the `or.sh` script, when the value of x we enter is less than 5 or greater than 13, we win the game. When it doesn't meet these conditions, we lose. <br/>

```.term1
cat or.sh
```

```
read -p "Type a value = " x

if [[ ( $x -lt 5 || $x -gt 13 ) ]]
then
echo "You won the game!"
else
echo "You couldn't win the game!"
fi

```

## Break and Continue
  
As we can see in the `select3.sh` example, we can stop our operations and loops with the exit and break commands, but the exit command actually closes the terminal, it does not close the loop we made. For example, you are using Google Chrome and you turn your computer off and on to close the Chrome browser. The break command just stops the loop then does not interact with the terminal.
Now let's examine the break command we will use for these operations. <br/>

```.term1
cat break.sh
```

```
#!/bin/bash

for x in {1..10..1} #that part can be (seq 2 2 100) also
do
    if [ $x -eq 3 -o $x -eq 5 ]
    then
        break #script will be stopped when x equals to 3 or 5
    fi
    pwd
    sleep 0.5
done

```
Unlike the break command, the continue command allows the program to pause rather than stop it. If we use continue instead of break in the example above, it makes the program stop at 3 or 5 instead of stopping when x is 3 or 5, so when x is 3 and 5, that block will not work. Let's look at the continue command with the same example.<br/>

    then

    fi
    pwd ; echo {$x}
    sleep 0.5
done
